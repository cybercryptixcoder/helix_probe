There is no database, no embedding, no graph. The library is just the adapter's knowledge text plus any --knowledge files, pasted in.

Retrieval: the same five sections every call, chosen by code

Nothing is searched. prompts.context() builds the prompt the same way every time. What it includes is decided by one rule: show in full what the current model gets wrong; compress what it gets right.

The box: the adapter's brief and probe format. Fixed.
Library: all of it. Fixed.
Your model: current version number, its fit and average match (computed by code), the beliefs, and the full predict() code.
Where your model is wrong: older experiments the current model mispredicts, newest first, at most 8, each with probe, observation and the current model's prediction.
The latest experiments: the last 5 in full (question, probe, observation, what the model of that time predicted, match).
Notebook index: one line per older experiment, at most 80, tagged [ok] or with its match score. Older than that: just a count.

Then the job text (PROPOSE, REVISE or SOLVE) is appended. So the prompt grows only with the model's size, the number of misses (capped) and the index (capped). In the live runs:

Prompt tokens per call. Grid run: 87 calls, largest prompt 6.7k tokens after 45 experiments; knob run: 52 calls, largest 3.6k. The context is 163k, so this is far from any limit. Growth flattens once the index cap (80 lines) is hit.

Failure 1 (grid): epicycles. Fit climbs to 100%, held-out stays near 10%

The very first experiment was a compound probe: five different buttons in one go from (4,4). The model read it wrongly ("C moves +x", "E moves −x by 2"). Every later single-button test contradicted those base beliefs, and each contradiction was absorbed as a local exception ("C moves −x on row 5 for x in {2,3,4,5}", "From (5,5), E is blocked") instead of the base belief being questioned. The proposer then kept probing near the exceptions (row 5, around (5,5)), so the exceptions kept multiplying. The model ends up memorising the notebook: 91% fit, 15% on new probes.

Three things in v1 make this easy: the REVISE prompt says "keep what still holds"; nothing checks a belief against its own evidence (the core beliefs cite only E1, which the model itself still gets wrong); and the proposer is drawn to the latest anomaly, so exploration collapses onto one corner of the board.

Failure 2 (knob): the words and the code disagreed, and the words won




By version 10 the code was nearly the true law (it missed only the clamp at x = 10 and the "a above 7 lifts y by 1" rule). But the beliefs written in the same reply said size = 1 + 0.5·max(a, c), which contradicts the code's correct |a − c|. Every later revision "fixed" the code to agree with the stale belief, broke size, and was rejected by the replay check (section 3). The model stayed at version 10 for the last 14 learn steps, and the proposer, seeing the same unexplained miss every time, asked essentially the same question (is x clamped at 10?) about ten times.


The guard worked: no bad model got in. But nothing let the system absorb what it had already found. The unchecked half of the model (the words) poisoned the checked half (the code).




What worked




    

  • Experiments are well designed: one variable at a time, each stating what the two possible answers would mean (knob E3 to E8 isolate each dial in turn).
    • 

  • When the model is right, using it works: knob box reached 5 of 5 goals on the first real try, by simulating candidates for free.
    • 

  • The context stays small and doesn't grow with the run (section 4).
    • 

  • The replay check catches every regression, and the held-out number exposes over-fitting that the fit number hides. Without held-out, the grid run would have looked like a success (fit 100% at step 20).
