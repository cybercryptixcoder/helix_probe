# Weight-Space Programming of Policies and Their Verification via Model Checking

- **Key:** arxiv-2611.11604
- **Authors / organisation:** Dennis Gross; artigo.ai (email affiliation only; no institution listed)
- **Date:** 2026-11-08 (arXiv v1)

- **Relevance to us:** 2 (useful)

## What they wanted, and why
The paper takes weight-space programming (an LLM writing a network's weights directly from a natural-language task description, no gradient descent) and asks how to make the result trustworthy. LLM-written weights can be wrong, and nothing in plain WSP checks them. The author also asks whether WSP can encode requirements that a scalar reward cannot express, such as "reach the goal while never doing X along the way". The larger goal is verified, gradient-free policy construction, plus a benchmark for WSP skill where a model checker provides exact ground truth.

## What they studied
Writers: DeepSeek-V4-Pro and Kimi-K3.1-Pro, both called through Ollama's cloud service. Targets: small feed-forward ReLU policy networks (argmax over action outputs). Frozen Lake: 1 feature, 4 actions, 1 hidden layer of 16. Transporter (taxi with fuel), Stock Market, and a safety variant of Transporter: 2 hidden layers of 32. Environments are PRISM MDPs with 17 to 16,496 states as built by Storm. Unit of analysis: the whole policy network and its induced Markov chain; individual neurons appear only in the LLM's own notes.

## How they did it
A three-step pipeline inside COOL-MC, none of it using gradients. Step 1 (creation): the LLM gets fixed instructions explaining how the network computes, a reminder of how ReLU pairs can form step functions and a later neuron their conjunction, the answer format, then the PRISM source with constants, the PCTL property and which direction is better, the rule that an unavailable argmax action is replaced by the alphabetically first available action, the input/output interface (which input is which feature, which output is which action, all weight shapes), and an optional natural-language description of the environment. It returns JSON with all weights, notes explaining what neurons compute, and 5 to 20 check states with intended actions. A validator checks JSON shape and finite values; a self-check runs the network on the check states and compares with the intended actions, catching arithmetic or transposition errors; failures are fed back (up to 2 retries). Step 2 (optional dataset repair): the LLM sees up to 200 misclassified states with Storm-computed optimal actions and edits the weights, up to 5 rounds or until 100% accuracy. Step 3 (model-checking repair): Storm computes the exact satisfaction probability; if the bound fails, the LLM gets the probability, the actions in up to 200 reachable states (unavailable-action states first), one simulated episode of up to 60 steps, and the best earlier network if better; up to 5 rounds. Later prompts show the LLM its earlier notes beside the weights so it edits its own design rather than reverse-engineering numbers. Temperature 0, seeds 1 to 3, thresholds set to the optimum minus 1e-4. RQ2 re-checks two-job transporter networks on a three-job model; RQ3 uses a fuel-reserve until-property.

## What counts as an explanation here
Not an interpretability paper. The written network comes with the LLM's notes stating which neuron implements which rule; the paper suggests (but does not test) that disabling such a neuron and re-running the model checker would show which safety property depends on it, and that an LLM could read a trained network's weights and point to responsible neurons, with model checking confirming or refuting the claim.

## How they judged success
Exact PCTL query probability from Storm (vs. the optimum over all policies), accuracy = fraction of Storm-built states where the network picks an optimal action, number of runs reaching the optimum, LLM calls per run, and counts of generation errors (invalid JSON, wrong shape, failed self-check, accepted despite failure, failed requests).

## What they found
All 18 RQ1 runs (3 environments x 2 LLMs x 3 seeds) reached the optimal probability straight after Step 1, so Step 3 never repaired anything in RQ1. Kimi's created networks picked optimal actions in 98.92% of states on average and 100% after Step 2; DeepSeek averaged 86.51% after creation (only 59.52% on Transporter, where two networks were at 39% yet still optimal in probability, because their wrong states are unreachable or irrelevant). RQ2: 2 of 3 networks per LLM also complete three jobs with probability 1; the others score 0. RQ3: all 6 runs satisfy the fuel-reserve property; in one run Step 2 raised accuracy from 37.9% to 98.4% but broke the property (probability 0), and one model-checking round restored it. RQ4: no invalid JSON; wrong shapes in 32 of 67 DeepSeek answers and 8 of 28 Kimi answers, almost all (38 of 40) a 32-row hidden matrix written with 30, 31, 33 or 34 rows.

## Limits and open problems they name
Only small networks, because every weight is emitted as text and the LLM must keep count; small environments (at most 16,496 states, two hidden layers of 32); three seeds and non-deterministic cloud inference, so numbers are indicative; two LLMs, one generalisation task, one safety property; the PRISM models and Frozen Lake are public, so contamination cannot be ruled out; the hand-written environment descriptions restate the model and other wordings might change results. Repair was barely exercised (23 of 24 created policies already satisfied their property). Future work: richer feedback naming violating states, writing weights neuron by neuron, sparsely, or via generated code.

## What we take from it
- **A measure:** accuracy over all states is a misleading proxy; a function-level verdict (here exact model checking) is what matters. For us: score a weight reader by predicted behaviour on reachable or relevant inputs, not by per-unit labels.
- **A protocol trick:** require the LLM to emit check cases alongside its answer and auto-verify them; this self-check catches encoding errors cheaply. Analogue for reading: ask the reader for concrete input-output predictions we can run.
- **A warning:** LLMs lose count in long matrices; layout and size of the presented weights matter.
- **A framing:** verified neuron-to-property attribution by ablation plus model checking is a ready-made test for a reader's claims about weights.

## K1 detail (reading setup)
- **Reader model(s):** This is a writing/repair study, not a reading study. Writers: DeepSeek-V4-Pro (deepseek-v4-pro:cloud) and Kimi-K3.1-Pro (kimi-k3.1-pro:cloud). Scores: both 9/9 runs optimal in RQ1; mean accuracy after creation 86.51% (DeepSeek) and 98.92% (Kimi); RQ2 2/3 each; RQ3 3/3 each. Reading occurs only inside repair (Steps 2 and 3), where the LLM reads its own current weights plus notes.
- **Target networks:** Feed-forward ReLU MLP policies, argmax over action outputs. Frozen Lake 1x16 hidden; Transporter, Stock Market, Transporter-safety 2x32 hidden. Parameter counts not stated. Written from scratch to act in PRISM MDPs (not trained).
- **How the weights were presented:** As numbers in JSON text (the LLM's own output, re-shown in later prompts with its notes). Number format and precision: not stated. Layout: per layer matrices and bias vectors with stated shapes; labelled inputs (feature names) and outputs (action names) via the interface section. Total tokens: not stated.
- **Prompt:** Fixed instructions (network computation, ReLU step/conjunction constructions, JSON answer format) -> task context (PRISM code and constants; PCTL property and direction; unavailable-action fallback rule; input/output interface and shapes; optional environment description) -> step task. Repair prompts add current weights, notes, a round log, step feedback, and the best earlier network. Prompt files: said to be in https://github.com/LAVA-LAB/COOL-MC/tree/wsp_verified; not inspected (access refused).
- **Access regime:** No tools for the LLM; it only writes text. The pipeline runs the network externally (self-check, dataset accuracy, Storm). Budgets: up to 5 dataset rounds, 5 model-checking rounds, 2 retries per request; temperature 0.
- **Controls:** No shuffled, untrained or prompt-only controls. References: Storm-computed optimal probabilities and optimal actions. RQ2 tests on an unseen three-job model as a generalisation check.
- **Failure modes:** Wrong matrix row counts (losing count in long matrices); failed self-checks (weights not encoding the LLM's own intended policy); dataset repair breaking a safety property; policies tied to the two-job instance failing on three jobs; one timeout.
- **Prompt/format choices that helped or hurt:** Showing the LLM's own notes next to its weights is motivated as letting it edit its design instead of decoding numbers (not ablated). The self-check catches encoding errors before verification. Long dense matrices as text hurt (shape errors); authors suggest neuron-by-neuron, sparse, or code-generated weights. Feedback that does not mark violating states is named as a limitation. No formal ablation of prompt or format.
