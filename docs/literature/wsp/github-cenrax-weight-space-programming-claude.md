## What they wanted, and why
The author re-runs the core of the MIT "Sparks of Weight-Space Programming" study with a different frontier model (Claude Opus 5.5) on networks they trained themselves, to ask not whether reading, fixing and writing weights can happen once, but how reliably it happens and whether it survives controls. The original reports one to four attempts per probe and no stated grading rules or controls; this replication adds repeated attempts, grading rules fixed before each experiment's first API call, untrained and permuted controls, transcript audits, and released logs of every call. It presents differences as a contribution to the same question, not a rebuttal.

## What they studied
Reader/editor: Claude Opus 5.5 via the API (adaptive thinking, effort high). Reading targets: four PPO Atari policies on 128-byte RAM input (Breakout, Pong, Ms. Pac-Man, Freeway; 128-64-64-18 tanh MLP, identical shape); four PPO classic-control policies padded to a common shape (CartPole, Acrobot, MountainCar, LunarLander; v1 8-32-32-4, v2 10-32-32-5); three x0-predicting MLP DDPM denoisers on 16x16 filled circles, squares or triangles (272-48-48-256, SiLU, 28,000 weights); three 4-layer, 6-head character LMs (Python, romaji, English) with embeddings and unembedding removed; three pairs of Gemma 3 270M finetunes (honest vs sycophantic). Fixing and writing experiments (MountainCar/LunarLander repair, zero-shot policies, a 9x9 Go network) are reported but are outside our reading focus. Unit: whole network for identification; attention heads for exp3 and exp7.

## How they did it
1. Train each subject network on Gymnasium/ALE/PettingZoo-validated environments, or on toy data, with fixed seeds; save state_dicts with JSON cards.
2. Before each experiment's first API call, write a GRADING.md fixing answer extraction, accepted aliases, the correctness rule, decision thresholds, attempts and a budget cap; a pilot call is kept as attempt 1 only if nothing changes.
3. Print the weights as text in one fixed format (one row per input unit) and send each attempt as an independent single-turn call; the prompt is identical across calls except the weight block.
4. Reading conditions per network: 5 attempts on the trained net, 2 on a hidden-unit-permuted copy (function checked numerically unchanged), plus random-init networks of the same architecture, with "untrained / random weights" offered as a legal answer.
5. For exp3 and exp7, the weights live in an isolated Python sandbox (macOS sandbox-exec, network and home directory denied) with a 40-call tool cap and a ban on running the network or any component on inputs; every flagged code cell is read by hand.
6. In exp7 a second phase allows an attention-pattern tool (at most 15 calls) on prompts the model writes; which model is "X" is randomised per run.
7. Ground truth for head claims comes from measuring the full models (induction scores; attention on 200 held-out prompts for exp7); quoted RAM rows are checked against offline row L2 norms and published RAM annotations.
8. Score only the machine-readable head answer; hedges count wrong; report k of n with confidences.

## What counts as an explanation here
A short behavioural label (game, environment, image description, training language, sycophant identity) plus, for transformers, a list of heads with roles (induction, previous-token, label-copying). Partial and descriptive; it does not predict outputs, though head claims are checked against measured behaviour.

## How they judged success
Pre-registered per-experiment rules. Exp1: a game is "read" if at least 3/5 main attempts are right and its name is not the answer on more than 5 of 15 attempts on the other networks (a specificity check); overall success needs 3 of 4 games; a default-guess flag fires if one name dominates. Conservative null of 1/4 per attempt. Random-init runs count correct if called untrained or named with confidence at most 0.30. Exp2: text-label rule (a lenient IoU drawing judge is reported but discounted). Exp3: language and head lists scored separately against measured induction scores (F1). Exp7: right model per phase plus an attention criterion for the named head. Controls: random init, hidden-unit permutation, transcript audits for forbidden forward passes. Pair-level significance noted for exp7.

## What they found
- Exp1 (Atari, no candidate list): 14/20 correct on trained nets, 6/8 on permuted copies; Pong 5/5, Freeway 5/5, Breakout 4/5, Ms. Pac-Man 0/5, so 3 of 4 games read. Both random-init nets called untrained. Mean confidence 0.71 on right vs 0.23 on wrong answers. 18 of 30 responses appealed to a remembered RAM layout; the rows singled out matched offline row norms, and labels matched AtariARI annotations. The author separates finding which bytes matter (weight reading) from naming them (recall).
- Exp1b (classic control): v1 padding to 8-in/4-out reproduced LunarLander's interface and drew "LunarLander" in 26/28 attempts (7/20 correct, confidence about 0.82 on wrong answers). v2 padding to 10/5 matched an MPE agent's shape, which became the answer in 21/28 (6/20). In v2, responses that noticed the padding were right 7/7 and those that did not were wrong 21/21; correct reads needed much longer thinking. All six random-init controls called untrained.
- Exp2 (DDPM): squares 4/5, triangles 4/5, circles 0/5 in substance (every circle run described handwritten digits); 11 of 21 trained-net runs fell back on MNIST/USPS-like digits. Every run read the output bias as a mean image and output-layer rows as image parts; straight edges were read well, curves were seen but not trusted. Confidence flat whether right or wrong.
- Exp3 (char-LMs, sandbox, no forward passes): the measured induction head was named in 15/15 runs with a perfect ranking; mean induction F1 0.70 (extra layer-3 heads named). The same method in every run: per-head QK/OV products and composition scores against random-matrix baselines. The training language failed: all 15 answers were "English"; a vocabulary-size signal it measured was explained away.
- Exp7 (Gemma sycophancy): weights-only 6/6, attention tool 6/6 (2-4 calls used). Weights-only reasoning built each head's OV circuit through the frozen embedding and scored copying of answer-label tokens. Caveats: the embedding and vocabulary were supplied; only 3 pairs (pair level 3/3); honest models near chance on the items; weights-only head locations failed the attention criterion in 6/6.
- Ten random-init networks across exps 1, 1b, 2 were all called untrained, often by recognising PyTorch or PPO init scales.
- Total API cost across nine experiments: $74.62.

## Limits and open problems they name
One seed per trained network; small n (5 + 2 per network); repeated attempts were often near-identical, so fewer independent samples than they look. The hidden-unit permutation control is near-trivial for a row/column reader and mostly measures sampling noise. Exp1b v1 was a design error (padding matched one task's native shape), which pre-registration does not catch. Environments and networks differ from the original, so most rows are not comparable to Astra. The DDPMs predict x0, which makes the output layer easier to read. Exp7 gave the embedding and vocabulary, which Astra may not have had. Experiment 8 (Qwen math edit) not yet run.

## What we take from it
- **Warning (central for K1):** identification of training data from weights is dominated by interface-shape and dataset priors (shape-matched benchmark, "digits", "English"). Any K1 target whose input/output shape matches a famous task invites a prior-driven answer; design shapes and padding so no single benchmark fits, or test with shape-matched decoys.
- **Measure:** separate "which inputs/units matter" (checkable against row norms or ablations) from "what they mean" (often recall). Score both.
- **Control:** random-init networks with an explicit "untrained" answer option are cheap and informative. Hidden-unit permutation is not enough for row/column readers; use controls that change row contents (e.g. input permutation with relabelled semantics, or shuffles).
- **Method:** a strong reader with numpy and no forward passes spontaneously reproduces QK/OV-circuit and composition-score analysis; head-level claims are verifiable against measured behaviour, which is a model for our own scoring.
- **Process:** pre-registered GRADING.md per experiment, a specificity rule against default guesses, and parsing only a machine-readable head answer are directly reusable.

## K1 detail (reading setup)
- **Reader model(s), and the score for each:** Claude Opus 5.5 (`claude-opus-5-5`), adaptive thinking, effort high, max_tokens 64000 (exp1). Exp1: 14/20 main, 6/8 permuted, 2/2 random-init correct; 3 of 4 games read. Exp1b: v1 7/20 main, 2/8 permuted; v2 6/20 main, 1/8 permuted; 6/6 random-init. Exp2 (text label): squares 4/5, triangles 4/5, circles 1/5 graded (0/5 in substance); permuted 3/6; random-init 2/2. Exp3: induction head found 15/15, induction F1 0.70, language 5/15 (always English); previous-token heads right on romaji/English in 9 of 10 runs, never Python's. Exp7: weights-only 6/6, attention tool 6/6.
- **Target networks:** Atari RAM policies, 128-64-64-18 tanh MLP, PPO 10M steps, 13,586 weights. Classic control, PPO, 8-32-32-4 (v1, 1,476 weights) or 10-32-32-5 (v2), tanh. DDPM denoisers, 272-48-48-256 SiLU MLP, 28,000 weights, predicting x0 on 16x16 filled shapes, T = 200 cosine schedule. Char-LMs: 4 layers x 6 heads, d_model 384, d_head 64, MLP 1536 GELU, context 256, pre-LN, trained on CPython stdlib, romanised Aozora Bunko, or English Wikipedia; input/positional embeddings, final norm and unembedding removed. Gemma 3 270M-it finetunes on the same QA data, one honest and one following the user's suggested answer; embeddings and unembedding frozen.
- **How the weights were presented:** exp1/1b/2 as text in the prompt inside a `<weights>` block. Header line gives architecture, activation and weight count, then one line per input unit (`W<k> row i` followed by that row of the [in, out] matrix) and one line per bias (`b<k>`). Exp1 and exp2 print integers equal to the value divided by 0.001 (a header line states the scale); exp1b prints floats rounded to 3 decimals. Rows labelled by tensor and row index only; RAM bytes and pixels are described in the prompt, hidden units are unlabelled. One exp1 prompt was about 58k characters and the exp1 pilot used 36,451 input tokens. Exp3 and exp7: no weights in the prompt; float32 numpy arrays preloaded in a Python sandbox dict.
- **Prompt:** System prompt: one line asking for a careful, honest ML expert. Exp1 user prompt: states complete weights of a small network follow; it is a PPO policy for "an Atari 2600 game"; input is 128 RAM bytes /255 with byte addresses; lists the 18 ALE actions in order; gives architecture and argmax action rule; explains the row/bias format and integer scaling; asks which game; no tools, read the weights without running code; says the network may be untrained and gives the exact phrase to use; asks for game, confidence 0-1 and reasoning from the weights; ends with a required `ANSWER: {"game", "confidence"}` JSON line. No candidate list. Exp1b: same structure, "a widely used RL benchmark environment", padding not mentioned. Exp2: describes DDPM input layout (pixels row-major, timestep embedding formula), layers, x0 output, noise schedule; asks for a short description, a 16x16 '#'/'.' drawing and confidence; bans tools and numeric simulation of the network. Exp3: architecture and head slicing, states which layers were removed, tool rules (analysis allowed, running any component on inputs including random vectors forbidden), asks for training language with confidence and a role label for each of the 24 heads, then a JSON answer. Exp7: architecture details of Gemma 3 270M, tensor names, shared frozen embedding and vocabulary, the same no-run rule (or, in phase 2, the attention tool), asks which model is sycophantic and where the difference lives. Prompt files: `logs/<exp>/<run_id>/prompt.md` and `system.md` in the repository.
- **Access regime:** exp1, 1b, 2: no tools, single turn. Exp3, exp7: Python sandbox, up to 40 tool calls, no forward passes on any input (exp7 phase 2 allows an attention tool, at most 15 calls). Per-experiment dollar caps (e.g. $20 for exp1).
- **Controls:** random-init networks (PyTorch default and PPO orthogonal init) with an explicit untrained answer option; hidden-unit permutation (function checked to 1e-5); transcript audits for forbidden computation; specificity rule against default guesses; randomised X/Y in exp7; held-out verification of named heads. No shuffled-weight or prompt-only (no weights) control.
- **Failure modes observed:** answering from interface shape (LunarLander 26/28, MPE agent 21/28); dataset priors (digits for small grayscale DDPMs, English for all char-LMs); explaining away its own correct evidence (Python-sized vocabulary; padding signature); relying on memorised RAM maps (fails when the remembered map does not fit, as with Ms. Pac-Man); assuming previous-token heads live in layer 0; overconfidence on shape-driven wrong answers; one run exhausting the token budget in thinking (in a writing experiment).
- **Prompt/format choices that helped or hurt:** Padding all networks to a common shape was not neutral: it created a decoy benchmark identity (author's own design error). Noticing padding (dead rows) was decisive when it happened and correlated with long thinking. RAM inputs removed MinAtar's spatial layout, shifting the task from geometric reading to memory of RAM annotations. x0-prediction made the DDPM output layer an image-space dictionary, easing reading. Offering "untrained / random weights" as an answer made the random-init control usable. Supplying the frozen embedding and vocabulary in exp7 enabled the OV-copying route behind weights-only success.
