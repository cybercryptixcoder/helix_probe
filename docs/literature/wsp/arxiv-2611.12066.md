## What they wanted, and why
Can an LLM write a working medical image classifier from medical knowledge alone, with no images and no labels? Labels are costly, but radiological reading rules are written down in textbooks, so they might be "compiled" into weights by an LLM. Unlike games, medical imaging has no source code for its rules, so this tests WSP where the LLM must bridge text knowledge and pixels. Three questions: does it work and do different LLMs write similar networks; how does it compare with a label-free foundation model and with few-label training; and how do written weights differ from trained ones.

## What they studied
Writers: Claude Opus 5.5 (via Claude Code headless) and GPT-6 Astra (via OpenAI Responses API). Target: ProgNet, a one-stage LeNet-style CNN on 28x28 inputs (10 conv 3x3 filters for the uterus task, ReLU, 4x4 average pooling to a 7x7 grid, linear read-out with one weight map per filter per output); 591 to 6,974 parameters depending on task. Tasks: ChestMNIST (14-label), PneumoniaMNIST, BreastMNIST, OrganA/C/SMNIST (11-class) from MedMNIST v2, and SynthUterus (anteflexion vs. retroflexion, synthetic MRI, 293 cases; public only since Feb 2026, low contamination risk). Unit: individual filters, read-out maps, biases, and the whole network.

## How they did it
One prompt per task, identical for both LLMs, with system prompt "Answer the user's request.", reasoning effort high, 128k output-token limit, fresh context, no tools and no MCP servers; three independent calls per task and LLM (42 calls total). Tool-freeness and single-turn were audited from logs. The prompt fixes the architecture and asks for prose design then an "edits" block in a small slicing DSL (all weights start at zero). Networks were scored on official test splits. Baselines: zero-shot MedSigLIP-448 (about 400M-parameter image encoder) and the same ProgNet trained with Adam on 256 class-stratified labels or the full training set (SynthUterus: all 117 training labels, 3 seeds); published ResNet-18 for orientation. Weight-level comparison against the 256-label Adam network: weight value distributions, filter images, and "evidence maps" (per-cell class-vs-rest logit contribution over test images) compared by Pearson correlation over the 49 grid cells.

## What counts as an explanation here
The network is interpretable by construction: each filter is a stated feature detector and each read-out entry a stated region-feature-class rule with the LLM's prose rationale. The paper treats this auditability as the main benefit; evidence maps provide a post-hoc check of where each network looks.

## How they judged success
Test AUC (MedMNIST official, averaged over findings/classes) and ACC, mean and SD over three calls; comparison with MedSigLIP zero-shot and Adam; Pearson correlation of evidence maps with Adam's; sparsity and number of distinct weight values.

## What they found
Mean test AUC over the six MedMNIST tasks: Opus 0.719, Astra 0.711, MedSigLIP zero-shot 0.588, Adam with 256 labels 0.828, Adam full data 0.892. Both LLMs beat MedSigLIP on 5 of 6 (not Chest); Adam-256 beats them on every MedMNIST task, by 10.9 (Opus) and 11.7 (Astra) AUC points on average. ChestMNIST stays near chance (Opus 0.552). SynthUterus: Opus 0.764 ± 0.073, Astra 0.136 ± 0.053 (systematically inverted), MedSigLIP 0.818, Adam 0.996. Astra's inversion came from modelling the bend at the cervix in the lower image, where these crops do not show it. Written weights are sparse and discrete: Opus 22–94% exact zeros and 8–145 distinct values per network versus Adam's 554–2,865 distinct values and no zeros; on SynthUterus Opus wrote four oriented edge detectors and left six filters empty. Evidence-map correlation with Adam is moderate where findings have typical locations (pneumonia +0.41 Opus / +0.65 Astra) and weak or negative elsewhere. Both LLMs set output biases from dataset class shares the prompt never stated (e.g. BreastMNIST about 73%, true 73.1%), evidence of dataset-specific knowledge; on SynthUterus all biases were zero.

## Limits and open problems they name
Tiny images and networks because all weights must fit one reply (answers up to 79k tokens); MedSigLIP handicapped by upsampled inputs and untuned prompts; SynthUterus synthetic, small, two raters without adjudication, some label noise; only two LLMs and one prompt; the prompt did not describe image layout, and a wrong guess inverted Astra; MedMNIST contamination cannot be excluded. Whether written weights help as initialisation is untested.

## What we take from it
- **A protocol to copy:** a fully specified, audited, single-reply, tool-free setting (tool list empty at init, no tool-use blocks, one turn), with raw logs released. This is the cleanest "no tools" regime in the WSP literature so far.
- **A warning about contamination:** LLMs bring dataset-specific priors (class frequencies) into weights; a low-exposure task is needed to separate knowledge of the benchmark from reasoning about weights.
- **A warning about unstated conventions:** missing layout information produced a sign-flipped classifier; a weight reader likewise needs input/output conventions stated, or must be tested for sign errors.
- **A measure:** evidence-map correlation between two networks of the same architecture is a simple, transferable way to compare a hypothesised (written or reconstructed) network with a trained one.
- **A signature:** LLM-written weights are sparse with few round values, unlike trained ones; a reader trained or prompted on written networks may not transfer to trained weights.

## K1 detail (reading setup)
- **Reader model(s):** None; this is a writing study. Writers: Claude Opus 5.5 (mean MedMNIST AUC 0.719; SynthUterus 0.764) and GPT-6 Astra (0.711; SynthUterus 0.136). Reading of weights is done by the authors (statistics, filters, evidence maps), not by an LLM.
- **Target networks:** ProgNet CNN (conv 3x3 bank, ReLU, avg-pool 4x4 to 7x7, linear read-out), 591–6,974 parameters, written (not trained) to classify 28x28 medical images; Adam-trained twins as references.
- **How the weights were presented:** Not presented to any model. Weights were written by the LLM as text in an "edits" DSL: plain decimal statements with slicing, fill, and +=/-=/*= operations, tensors named CW, CB, M, B, every weight starting at 0. Precision free (examples use 3 decimals, e.g. -0.111). Total tokens: answers up to 79k (including reasoning).
- **Prompt:** Fixed structure: YOUR TASK (write weights from scratch, no training, no tools, no images, single reply, describe design then write edits) -> THE DATASET (name, task type, official description, label list) -> THE INPUT (28x28, channels, pixel scaling to [-1,1], row/column convention) -> THE OUTPUT (logit semantics per task type) -> THE NETWORK (equations, tensor shapes, parameter count, cross-correlation convention, zero init) -> HOW SCORED (metric, comparison with gradient-trained baselines) -> HOW TO WRITE (DSL with worked example). No image layout or class statistics given. Public: `prompts.py` in the repo; full SynthUterus prompt in supplementary Fig. S1; per-call `prompt.txt` under `runs/`.
- **Access regime:** No tools, no code execution, no forward passes, no feedback, single reply; reasoning effort high; 128k output tokens; fresh context per call; audited.
- **Controls:** Zero-shot MedSigLIP; same architecture trained by Adam (256 labels, full data); ResNet-18 reference; low-exposure SynthUterus task as a contamination control; three independent calls per condition. No shuffled-label or random-weight controls reported beyond chance level (AUC 0.5).
- **Failure modes:** Near-chance on subtle, rare multi-label findings (ChestMNIST); systematic sign inversion from a wrong assumption about image layout (Astra on SynthUterus); reliance on memorised dataset statistics; coarse region features where trained networks use precise organ locations.
- **Prompt/format choices that helped or hurt:** The architecture was chosen shallow so each weight has a direct meaning that maps to a rule (stated design rationale). Not describing image layout hurt (inverted Astra). Asking for a design description before the edits block is part of the protocol (not ablated). No prompt ablations; authors note other prompts may change results.
