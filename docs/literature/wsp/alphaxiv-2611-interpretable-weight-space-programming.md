## What they wanted, and why
Neural networks predict well but are opaque, which is a serious problem in science, where explanation is the aim; neuroscience encoding models are the motivating case. The authors propose interpretable weight-space programming (iWSP): an LLM agent writes a model's weights and features directly in code, with training forbidden, and revises them using only a validation score. Without backpropagation the agent must use prior knowledge, so each change comes with a written rationale. The larger goal is to align highly predictive scientific models with human-readable theories.

## What they studied
Writers: Claude Code with Opus 5.5, Sonnet 5.5 and Haiku 5.5 for algorithmic/NLP tasks; Opus 4.7 for story fMRI and ECoG; Gemini 4 Carbon for visual cortex. Targets: small GPT-style transformers (default three layers, width 64, agent may change the architecture) for 13 algorithmic tasks and 4 NLP tasks (TREC, SST-2, MRPC, SNLI); feature-extracting networks feeding a fixed ridge regression for LAION-fMRI and NSD visual cortex, story-listening fMRI (one subject), and ECoG responses to audio (one patient plus five more). Unit: whole model, its heads, MLP units and named computations.

## How they did it
Each run gets a Python file with a model and an empty weight-writing function, a non-editable evaluator, and a rules document forbidding optimizers, fitting loops, pretrained weights and computing the answer outside the network; interpretability is requested in the prompt, with parameter count as a proxy. The agent iterates for a fixed number of steps (30 to 50 per algorithmic/NLP run; hundreds for neuro), seeing only a visible-set score. For brain data, the evaluator fits ridge regression from the written features to responses and returns Pearson correlation; features are capped below 10,000. Afterwards: an LLM judge audits every saved model for training and rule violations; weight-writing code is rerun on altered task data to verify weights do not depend on data; models are rescored on a hidden set. Readability test: Opus 5.5 describes the best model in at most 200 words, and fresh sessions rebuild it from that text alone; a control rebuilds with no description. Each algorithmic/NLP task ran twice per Claude model, about 1,340 iterations per model.

## What counts as an explanation here
The model itself, written as a program whose every weight and feature has a stated role (e.g. subtractive Euclid as a repeated three-ReLU block; a keyword-and-negator sentiment pipeline; Gabor energy, surface geometry and contour-curvature features). Complete by construction for algorithmic tasks; for neuro models, explanation is the decomposition of predicted variance into named computations. A 200-word description that suffices to rebuild the model is taken as evidence of readability.

## How they judged success
Exact-match accuracy on 200 visible and 2,000 hidden examples (algorithmic), official test splits (NLP), majority baseline; parameter count of the smallest 100%-accurate model; voxelwise Pearson correlation against seven classical interpretable baselines, their combination and AlexNet, zero-shot on NSD and on held-out subjects; unique variance by refitting without each computation; GPT-2 XL baseline (story fMRI); Whisper and one-shot textbook acoustic features (ECoG), with bootstrap intervals over electrodes. Rebuild fidelity: hidden accuracy, parameter ratio, error correlation and output identity with the original, against a no-description control. Audits by LLM judge and altered-data reruns.

## What they found
All 26 Opus algorithmic runs reached 100% on visible and hidden sets, often by implementing a known algorithm; TREC reached 87.3% hidden accuracy and three of four NLP tasks beat majority, paraphrase did not. Algorithmic runs hit 99% visible accuracy within the first tenth of iterations and then compressed from about 3,400 to about 200 parameters; median smallest 100% model was 166 parameters for Opus, 41,600 for Sonnet, 100,000 for Haiku. One Sonnet run fit models to labels and was excluded. All rebuilt algorithmic models reached 100%; NLP rebuilds lost about 1.4 points; rebuilt algorithmic models had 1.74 times the original's parameters versus 2,043 times for the no-description control. Visual cortex: on NSD, iWSP beat all seven interpretable baselines in early (0.443 vs 0.400) and ventral (0.317 vs 0.256) cortex, matched AlexNet in early and trailed it in ventral (0.391). Story fMRI: a jump from 0.067 to 0.104 came from story-position features, exposing a scan-edge confound. ECoG: 0.074 vs 0.082 for Whisper on grid electrodes; combining both improved over Whisper alone.

## Limits and open problems they name
Agents recombine known motifs rather than invent new principles; models are shallow (no deep hierarchies without backprop), which likely explains trailing deep models in ventral cortex, hard language and speech. 100% on the eval does not guarantee correctness on all inputs. The method relies on the agent's explanations staying faithful to its edits; stronger agents need continued vetting. Costly (about $17,500 total). Neuro results are observational with few subjects. Harness cannot stop the agent's own Python from training, so rules are audited after the fact.

## What we take from it
- **Ground-truth targets for a weight reader:** hand-written transformers with full descriptions, at sizes down to tens or hundreds of parameters, are ideal K1 test networks (known answer for every unit). The six example descriptions in Table A3 show the level of detail available.
- **The text-bottleneck test** (describe in at most 200 words, rebuild in a fresh session, compare with a no-description control) is a usable, reviewer-recognisable metric for "the reader understood the network". We can invert it: have a reader produce the description from weights, then rebuild.
- **Audit methods:** altered-data reruns and LLM-judge audits to detect covert fitting.
- **Future-work hook:** the authors suggest approximating black-box models with interpretable networks, which is close to our white-box-surrogate goal; we should position against this.

## K1 detail (reading setup)
- **Reader model(s):** No weight-reading task with a score. The closest reading step is Opus 5.5 writing a 200-word description from a model's *code* (not from raw weight tensors); rebuilds by fresh Opus 5.5 sessions reached 100% hidden accuracy on all 13 algorithmic tasks and lost about 1.4 points on NLP. Writers: Opus 5.5, Sonnet 5.5, Haiku 5.5, Opus 4.7, Gemini 4 Carbon.
- **Target networks:** Hand-written GPT-style transformers (default 3 layers, width 64; final sizes from tens of parameters to around 190,000 for NLP) for algorithmic and NLP tasks; hand-written feature networks (e.g. an 865-line visual program producing 9,996 features; 3,852 audio features) feeding ridge regression to predict brain responses. None trained.
- **How the weights were presented:** Not presented as tensors to any reader. Weights exist as Python code (closed-form assignments, constants, NumPy/PyTorch). Description sessions read the code. Precision: some models require float64 (stated for multiplication). Token counts not stated.
- **Prompt:** Writing prompt summarised in the paper (rules quoted in part in Sec. 2): never train; set parameters in closed form; maximise accuracy; prefer interpretable structure, parameter count as a proxy. Prompt files are in the repo (`experiments/evolve/program.md`, `experiments/evolve-neuro/program.md`; not re-read here). Description prompt: describe the best model in at most 200 words; rebuild prompt: the description plus the task only. Exact description and rebuild prompt texts not given in the parts read; scripts are in `experiments/nl-bottleneck/`.
- **Access regime:** Writers: restricted Claude Code session with six file and shell tools, no web, reads confined to the run folder, may run only the model file; visual cortex search fully sandboxed; story fMRI and ECoG searches not sandboxed. Budgets: 30 to 50 iterations per algorithmic/NLP run; 600 (visual), not stated in the text for story fMRI (its figure axis runs past 200 iterations), 902 (ECoG).
- **Controls:** Majority baseline; no-description rebuild control; altered-data reruns; LLM-judge audit; classical and black-box baselines for neuro; held-out dataset and subjects. No shuffled-weight control (not applicable).
- **Failure modes:** Fitting to labels (one Sonnet run); iterations whose code could not be rerun (31 Opus, 215 Sonnet, 27 Haiku); lookup-style or very large solutions in no-description controls (e.g. a 207-million-parameter TREC rule list); exploitation of a dataset confound (scan-position features); paraphrase below baseline.
- **Prompt/format choices that helped or hurt:** Two sentences on learning the task format were added to Sonnet and Haiku prompts because their first sessions stopped early. The interpretability preference drove compression after accuracy saturated. No ablation of reading formats.
