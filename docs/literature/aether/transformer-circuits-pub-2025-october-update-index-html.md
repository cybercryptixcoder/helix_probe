- **Relevance to us:** 3 (central) — not for its results, which are qualitative almost throughout, but for the **perceptual-versus-motor distinction** and for the fact that it is the folder's only entry where a "steering works" claim is made about *symbolic* output rather than token-level behaviour, which exposes exactly what a steering claim needs.

## What they wanted, and why

Two unrelated questions in one month. Post 1: an earlier paper from this team showed models build mechanisms for low-level *visual* properties of text — where a line breaks, whether a table is aligned. Does the same machinery extend to higher-level *semantic* visual content, i.e. can a model that only ever sees text recognise the eyes in an ASCII face, and hold the concept of eye across a code format (SVG) and a prose format in several languages while doing so? And if a feature recognises a smile, does it also contain the information needed to *draw* one — a distinction the authors state explicitly as not implied by the perceptual result. Post 2: a purely engineering question. Dictionary learning is usually initialised randomly, but model activations are not isotropic; if you seed your dictionary atoms with real data points instead, do you get better dictionaries for the same training budget?

## What they studied

Post 1 studies features from sparse autoencoders trained on a **middle layer** of two models: Claude Haiku 3.5 and Claude Sonnet 4.5 base. The stimuli are text-based depictions — ASCII smiley faces, SVG faces, an SVG dog, a hand-drawn SVG dog, and the "pelican riding a bicycle" SVG popularised by Simon Willison as an art benchmark — plus plain-text sentences about the same concepts, in several languages. The authors note that all comments and descriptive labels were stripped from the stimuli, so the model is not being handed the answer in a metadata field. Post 2 studies the SAE itself: dictionaries over the residual stream of a **pretrain-only Claude Haiku 4.5**, plus one weakly-causal-crosscoder (WCC) variant, with an explicit statement that results hold on other subject models.

## How they did it

**Post 1, perception.** Generate faces, find a feature that fires on the eyes, then vary the input to see what the firing depends on. Three manipulations carry the argument. (a) *Context minimisation*: strip the face down until the feature stops firing — for the ASCII face it survives on a single underscore (the forehead), a slashed forehead, and two `@` characters, i.e. the feature keeps firing while there is enough context to predict that these are parts of a face, and stops when there is not. (b) *Context displacement*: give the model a full, rich face and then move the eye element *above* the context that establishes it as a face; activation disappears. A lone `@` without preceding ASCII-art lines does nothing, and in SVG an eye-like circle fires only after a circle that establishes the face outline, with sensitivity reported to ASCII line character counts, SVG circle colour, and the parent element's width and height. (c) *Reordering*: shuffle the elements of the dog SVG. The left eye moved above the torso loses its activation while the other eye and the pupils keep theirs, and when the mouth and tail paths are moved away from the eyes a red rounded rectangle (the collar, and even its bell) takes over as the strongest "mouth/lip" — which the authors themselves flag as an open question, since proximity is an equally good explanation as shape. On the hand-drawn dog, reordering reveals a nose feature that was silent when the nose happened to be defined before the eyes. They also report features whose *top logit effects* concern that concept — a "say smile" feature activating on tokens most often followed by "smile" — sitting on the ASCII face just before the smile, plus a size-perception feature on the forehead slashes.

**Post 2, initialisation.** Data Point Initialization: draw as many random data points as there are features, zero-centre them by their mean, blend each with a Kaiming-initialised random vector under a scalar, and stack the blends as the encoder columns with the decoder set to the transpose. The scalar interpolates between pure random (0) and pure data-point (1) initialisation; the reported operating points are 0.8 for the SAEs and 0.4 for the WCCs. Their stated intuition is that activations are anisotropic, so seeding atoms in the high-density region should start training with both better sparsity and better reconstruction. They tried tranche sampling and block-copy variants of the initialisation and report that none consistently beat the base version.

## What counts as an explanation here

Post 1's account is **feature-level and mechanistic but not circuit-level**: a dictionary feature is doing the work of a concept, and the explanation of a behaviour (recognising, or drawing, an eye) is that this feature fires in the right place and that removing or adding it changes the behaviour. The dependency on context is explained as prediction: the feature is not a shape detector but a *shape-in-a-frame* detector, which is what the context-minimisation and displacement manipulations are built to show. The authors are explicit that the encoding side of this — what computation turns low-level text into these features, and whether the model has an internal picture it plans and then draws from — is **outside** what they claim, and they list it as future work. Post 2's explanation is not mechanistic at all; it is an inductive bias argument (initialise where the data lives) validated by a downstream metric, and "more importantly, this works empirically" is the sentence that concedes the point.

## How they judged success

Post 1 has **no quantitative criterion**: success is that the feature fires on the semantically corresponding element across ASCII, SVG and prose, that it stops firing when the framing is removed or displaced, and that steering produces the semantically corresponding change in the output. The steering setup is one prompt: Sonnet 4.5 base is given a simple SVG smiley as a style reference and asked to make a similar one, and features are then steered at various strengths. Results are: negative steering on the "say smile" motor feature yields a frown from the same prompt (and also frowns the ASCII smiley studied earlier); sweeping the steering strength yields an ordered progression with a straight-mouthed neutral face as the midpoint between smile and frown; positive steering on "say cat" adds ears, whiskers and a muzzle; a "say wrinkles" feature adds wrinkles; style — bold colours, circular geometry — is preserved across all of them. A `say unicorn`-type transformation of faces is mentioned in the conclusion. Crucially, the authors observe that **motor** features (those with top logit effects for the concept) were the effective ones for steering while perceptual features were not, and they list "what characterises a feature that is useful for steering, and can we find them automatically" as an open question. Post 2's criterion is the conventional one: sparsity (L0) and reconstruction (MSE) at matched training, reported as percentage changes.

## What they found

Post 2 gives the only numbers in the update, and they are modest and honest. For the largest SAE (524k features) the reported gains are about **17% lower L0 and about 4% better MSE**; for the WCC the gains are smaller, roughly **1% lower L0 and about 2.3% better MSE**. The direction is consistent across model sizes, which is the stronger part of the claim. Post 1's findings, in the prose's own terms: features for specific parts (eyes, mouth, nose, ears, legs, head) appear in models from Haiku 3.5 to Sonnet 4.5; the *same* eye, mouth and nose features fire on both the SVG and the ASCII face; features transfer to a human-drawn SVG once ordering is fixed; the pelican-on-a-bicycle SVG yields bike, wheel, foot, tail, eye and mouth features plus a "soft/fluffy texture" over the wings and a low-activating "bird" motor feature; activations survive colour and radius changes but depend on framing and on code order; and steering on motor features edits the drawing semantically while keeping its style. The authors name what they observe as the model doing face pareidolia — seeing a face where only a shape exists — and note the ears and nose activating as candidate eyes in the rearranged dog.

## Limits and open problems they name

Post 1: only concrete entities were tried, so whether features exist for abstract properties like aesthetic or artistic style is open; perceptual-versus-motor is asserted from a handful of examples with no characterisation of what makes a feature steerable; there is no account of how these features are computed from text, nor of any internal "picture, plan, then draw" representation; and the collar-as-mouth case is put forward with two live explanations (shape versus proximity) and explicitly deferred. Post 2 has no limits section at all — the page ends after the operating-points sentence, and the authors' one contextual remark is a credit edit noting prior work on informed initialisation by Peigné and saying their contribution is showing the effect in real models.

Limits we add, not theirs, and the substance of this entry: (1) Post 1's **recognition results are a search problem with a favourable selection** — the procedure is "find a feature that fires on the eyes", so a null result is impossible by construction, and no rate is given for how many features in the dictionary fire on the right element versus how many fire on the wrong one. The one number that would make this a measurement, the fraction of body-part features whose strongest activation lands on the correct part, is absent. (2) The **steering demonstration has no direction control**: no random feature of matched firing statistics, no equally-normed random direction, and no statement of the perturbation's norm relative to the residual stream, which is the bookkeeping a previous entry in this folder had to invent for itself precisely because steering effects get read as linear-representation evidence. (3) The **perceptual-versus-motor asymmetry is reported as an observation, not tested as a claim** — one would want, for the same concept, the perceptual feature's logit effects and the motor feature's activation profile compared on identical inputs, and instead the two are drawn from different searches. (4) Post 2's gains are measured against a random-initialisation baseline only; the relevant comparison is against other ways of spending the same compute (longer training, more resampling, better decoder-norm handling), and a 17%/4% shift at one scale with 1%/2.3% on the crosscoder is the kind of effect size that can also come from a better-conditioned optimiser rather than better atoms in any interesting sense.

## What we take from it

- **Perceptual and motor are different objects and should never be reported as one feature.** The clearest reusable idea in the month: a feature that reliably activates when a concept is present need not contain the information needed to *produce* it, and this post is the first place in the folder where the split is made on outputs we can inspect by eye. Any steering claim of ours should say which of the two it is using, and the search for steerable features should start from top-logit-effect rankings rather than from activation strength — the authors say the motor features were the ones that worked, and even offer the mechanism plainly: their top logits are the concept.
- **Framing is part of the input, so a feature is a detector for a shape-in-a-context, not for a shape.** The single `@` does nothing; the same `@` under two lines of ASCII head fires the eye feature; displacing the eyes above the establishing context switches the feature off even though the picture is now *richer*. Import the two manipulations as a standard pair — minimise the context until the feature dies, then add full context but displace the target out of it — because they separate "needs more evidence" from "needs the right frame", and the second is the one that catches a feature that is really a position or proximity detector.
- **Reordering is a free causal test on structured formats.** For any input with an order (code, tables, markup, reasoning traces), permuting elements while holding content fixed shows which features are bound to content and which to position — and it caught a real feature (the nose) that was silent purely because of where it sat in the file. Cost: one forward pass per permutation, no retraining.
- **An initialisation that seeds atoms in the data manifold is cheap and real, but its effect size must be priced against the alternatives.** A 17% L0 reduction at 524k features for a two-line change to constructor code is worth knowing about, and the anisotropy argument for why it should work is sound. But this is a training-efficiency result, not an interpretability one, and the honest framing is "this buys you sparsity at fixed wall-clock", which has to be weighed against simply training longer — the same shape of question as the checkpoint-Pareto control demanded of ablation fine-tuning elsewhere in this folder.
- **Beware the search-shaped result.** "We found a feature that does X" is unfalsifiable unless paired with the denominator. When we write up a feature discovery, state how many features were examined and how many satisfied the criterion, or the finding is an anecdote with pictures — and pictures are exactly what makes this post persuasive.
