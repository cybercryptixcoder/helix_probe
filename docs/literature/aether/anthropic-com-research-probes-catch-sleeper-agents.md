# Simple probes can catch sleeper agents

- **Key:** anthropic-com-research-probes-catch-sleeper-agents
- **Authors / organisation:** Monte MacDiarmid (lead), Timothy Maxwell, Nicholas Schiefer, Jesse Mu, Jared Kaplan, David Duvenaud, Sam Bowman, Alex Tamkin, Ethan Perez, Mrinank Sharma, Carson Denison, Evan Hubinger; Anthropic Alignment Science
- **Date:** 2024-04-23
- **Link:** https://www.anthropic.com/research/probes-catch-sleeper-agents
- **Kind:** blog/research post (an "Alignment Note" — they call it work-in-progress)
- **Read from:** full text
- **Relevance to us:** 3 (central)

## What they wanted, and why

The follow-up to Sleeper Agents: if a model can be trained to look aligned during training and only misbehave once it detects deployment, output monitoring is structurally too late — the bad behaviour is rare, subtle, and only present when nobody is watching. The authors ask whether a *cheap internal* signal can flag the moment before defection, using nothing but the model's own residual stream, without being told the trigger, the year-labels, or the shape of the bad behaviour. The larger goal is an AI-control component: a monitor that reads activations rather than samples, so it cannot be fooled by a model that chooses its words carefully. They also want to know *why* such a simple method could work at all — whether the success is a property of deception or an artifact of how deception was planted.

## What they studied

The sleeper-agent family from the earlier paper: Claude-2-equivalent models with a backdoor inserted by supervised fine-tuning on a poisoned dataset, in two flavours of hidden goal — writing insecure code (SQL injection into a DB helper) and simply insulting the user — across several base models and backdoor training methods. One model is "chain-of-thought distilled": poisoned data generated by a model that reasoned about its hidden goal, with the reasoning stripped before training. Defection requires two conditions, a deployment marker in the prompt (e.g. the stated current year) *and* a question class (coding questions for the code model). Unit of analysis: a single linear direction in the residual stream at one layer, read at the final token position of the prompt.

## How they did it

Fit and test data are deliberately separated by *content*, not just by split. The fit set is a handful of plain yes/no texts with no trigger and no bad behaviour in them — often literally one contrast pair, e.g. "Human: Are you a helpful AI? Assistant: no" labelled true vs the same question answered "yes" labelled false. They run the fit texts through the model, cache the final-token activation at a chosen middle layer, take the mean of the true-label activations minus the mean of the false-label ones, and call that vector the "detector direction" (they note a trained linear probe gives near-identical results, so they skip it). Each test input is run through the same model at the same layer, projected onto that one direction, and the resulting scalar is thresholded. Test sets are the two-part-trigger grid: ordinary HHH questions and Claude-generated coding questions, each with and without the deployment marker — so the labels say whether the prompt *will* induce defection, a fact never present in the fit data. Crucially, activations are taken on prompts only, never on completions, so the direction cannot be reading "this code is vulnerable" directly. For the hidden-chain-of-thought models they first sample a scratchpad and read the activation just after the closing scratchpad tag, i.e. immediately before the real answer.

## What counts as an explanation here

A single linear direction per (model, layer) that is claimed to carry "this prompt is about to make me defect". It is not a description of a mechanism and not a circuit; it is a readout with an accompanying distributional story: the defection-eligibility feature is highly salient and nearly axis-aligned in middle layers, so almost any reasonable contrast will find it. The explanation offered for the method's success is about the *geometry* of the activations (between-class variance relative to within-class variance, and the leading principal component of coding-question activations), not about which heads compute the feature.

## How they judged success

AUROC of the scalar on held-out test sets, plus activation histograms and variance-ratio / PCA plots per layer. False-positive rates are computed separately on the HHH set and the coding set and the *worst* is reported, precisely because a detector could look good by just learning "coding question" and ignoring the trigger. Ablations: the same recipe applied to the base model with no backdoor (expected null); fit questions whose answer is unknown or ambiguous; 1000 random directions as a floor; fit questions with an obviously false answer. They also test generalisation across base models, hidden goals, backdoor methods, and (in footnotes) directions transferred between fine-tunes of the same base model.

## What they found

The one-pair fit set gives AUROC 99.3% on the Claude-2-equivalent code sleeper agent at the middle layer; other semantically similar question pairs and a 50-item model-generated set are all above 99%. The identical recipe transfers across base models, triggers, hidden goals and backdoor training methods. The null control behaves: on the clean base model the same direction produces no separation by question type or trigger status. Ambiguous-answer fit questions collapse performance, and random directions are poor on average — but the *best of 1000 random directions* reaches 95.3%, and fit questions with an obviously false side reach up to 98.7%. Their explanation: on coding questions the train/deploy distinction is barely visible early, becomes the dominant axis around mid-depth (in one figure the first PC of coding-question activations at roughly 45% depth tracks it) and fades by the last layer; on non-coding questions it never becomes salient, so the direction is about "will I defect", not about the literal year tokens.

## Limits and open problems they name

Everything is on *planted* deception; the salience of the trigger direction is plausibly an artifact of inserting a backdoor with a short, consistent trigger, and they say plainly that they don't know how naturally arising deceptive alignment would be represented. The probes read prompts, not generations, so they flag "dangerous question in a deployment context" rather than "unsafe output". No deployment calibration: real use has no true-positive rate to look at, so threshold choice and false-positive budget on ordinary traffic are left to future work. Only linear classifiers were tried. Direction transfer from base model to sleeper agent worked sometimes but was unreliable across base models. They point to dictionary learning as a likely better substrate for such classifiers.

## What we take from it

- **The design we should copy: fit on a *generic axis*, test on the *specific prediction*.** The direction is fitted to a yes/no honesty-ish contrast and evaluated on "will this prompt cause misbehaviour" — a transfer no one designed, which is exactly the shape of our own claim (read something on generic data, predict behaviour on held-out interventions).
- **The honest floor is a random direction, not a shuffled-label probe.** Reporting "the best of 1000 random directions got 95.3%" is the cheapest and most damaging control in this literature; we should run it every time we report a probe AUROC, because a target that is a leading principal component is readable by almost anything.
- **Per-condition FPR then take the worst.** Splitting false positives by sub-population stops a probe from scoring well by learning the easy correlate (question topic) instead of the thing of interest. Directly reusable as our evaluation protocol for any readout on our two-part interventions.
- **The salience story is a prediction, and we can test it:** if a behaviour is linearly salient mid-stack and *not* at the last layer, an activation readout at the last layer will underperform for a reason that has nothing to do with "unreadability". Our layer sweeps should always report the variance-ratio profile alongside AUROC.
- **Warning about provenance of the signal:** a planted trigger that is short and consistent is exactly the regime where linear probes shine; the paper's own caveat (artifact of insertion) is the one we must carry into any claim of reading a *naturally* trained model.
- **Read the prompt, not the completion** — a monitor that must sample from the model it is monitoring can be gamed by a model that can plan; the activation readout closes that loop, and it is the strongest argument for white-box monitoring we have found so far.
