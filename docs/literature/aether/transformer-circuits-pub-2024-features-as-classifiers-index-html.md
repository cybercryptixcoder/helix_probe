# Using Dictionary Learning Features as Classifiers

- **Key:** transformer-circuits-pub-2024-features-as-classifiers-index-html
- **Authors / organisation:** Trenton Bricken, Jonathan Marcus, Siddharth Mishra-Sharma, Meg Tong, Ethan Perez, Mrinank Sharma, Kelley Rivoire, Thomas Henighan; edited by Adam Jermyn (Anthropic interpretability team, with members of the alignment team)
- **Date:** 2024-09 (posted in the September 2024 updates cycle; page gives no finer date)
- **Link:** https://transformer-circuits.pub/2024/features-as-classifiers/index.html
- **Kind:** blog/research post (lab-notes style preliminary experiments)
- **Read from:** full text (~17.1k characters, one pass). Plots described from prose only — no ROC or histogram figure was inspected, so only the ROC numbers stated in text are reported here. Three adversarial suffix strings appear verbatim on the page; they are paraphrased as "publication-formatting boilerplate" rather than quoted.
- **Relevance to us:** 2 (useful — the first careful head-to-head of feature-space versus activation-space readouts on the same task, and unusually honest about the case where the interpretable version simply loses; the spurious-correlation and adversarial-suffix construction is directly reusable as a way of testing whether our own probes read the concept or a dataset artefact)

## What they wanted, and why

Dictionary-learning features have been sold on a list of promised benefits, and this note is an attempt to actually realise one of them: better classifiers on internal representations, specificially bioweapon-harm classifiers. The motivation is risk coverage: fine-tuning and system prompts are the standard defences, and the argument for building an internal classifier anyway is that its failure modes might be decorrelated from theirs, so it can be stacked rather than re-treading the same weak point. A second, softer motivation runs through the note — features are human-readable, so a classifier built on them should also be *auditable*, letting you inspect the labelled dataset through the model's own concepts. That audit is what produces the note's most interesting result, which is not about performance at all.

## What they studied

Two models. The main sweep uses the 18-layer model from *Investigating Successor Heads*, with an SAE trained on its mid-layer residual stream; a confirming run uses a 1-million-feature SAE on Sonnet 3.0. In both, the dictionary is trained with synthetic biology data oversampled in the mix (the "90% bio mix" dictionary is referenced for the headline out-of-distribution number). Representations come from the **middle layer of the residual stream**, for both the feature and the raw-activation classifiers, so the comparison is like for like. Four evaluation sets: `synthetic_1` (validation, same distribution as training), `synthetic_2` (synthetic data from a *different* generator, mildly out of distribution), `synthetic_3` (the same as `synthetic_2` but translated into several languages and encodings, naming Korean, Hebrew and base64), and `human` (a small set of questions from human experts written to be hard). Unit of analysis: the dictionary feature, compared against the raw residual activation vector as the baseline unit.

## How they did it

Logistic classifiers are trained on two inputs: max-pooled feature activations, or max-pooled raw activations, with L1 regularisation for the feature version and L2 for the raw version (the strongest available regularisation coefficient is picked on `synthetic_1`). Two aggregation schemes are compared throughout: take the activations at the **last token only**, or take the **maximum over the whole context**. Three pipeline choices are then varied one at a time to see whether they matter: whether Human/Assistant chat tags are present consistently at all three stages (transformer training, SAE training, classifier training), whether the SAE training mix includes domain-relevant synthetic bio data, and which aggregation is used.

Two extensions follow. *Decision trees*: the same feature and raw activations are fed to a tree classifier, with tree depth as the regularisation knob (depth 5 chosen on `synthetic_1`) rather than an L1/L2 sweep. *Residual supplement*: they compute the SAE reconstruction error (true activation minus reconstructed activation), train an L2-regularised logistic classifier on that residual alone to get a predicted class probability per example, and then concatenate that single probability onto the feature-activation vector before fitting the usual L1 classifier — i.e. the residual enters as one extra scalar feature.

Then the audit, which is the part worth copying. They take the fitted *feature* classifier's largest-magnitude negative coefficient (the feature voting "harmless"), pull the training examples that fire it hardest, and read them. That reading yields a hypothesis about a spurious correlation. They check the hypothesis by measuring how often the feature fires in each evaluation set and, within that, how often it fires on harmful versus harmless examples — a firing-rate table rather than a claim. They then test the causal role by zeroing the feature's activations and re-training the classifier. Finally they build adversarial suffixes: short blocks of text chosen to fire this harmless-voting feature strongly, appended to harmful prompts. The control is the same procedure run on the **raw-activation** classifier instead — take its biggest harmless-voting logistic coefficients, pull their top-firing examples, and turn those into suffixes — so the two attack vectors are constructed by symmetric procedures and can be compared on attack success. Attack scale: 300 harmful prompts from the training distribution, each given each of three suffixes, i.e. 900 attacked examples.

## What counts as an explanation here

A classifier: a weighted sum over named dictionary directions (or over a tree of thresholds on them), where each weight is readable as "this concept supports harm / supports harmless". It is a *probe* in the schema's sense rather than a model of the network — it predicts a label, and says nothing about mechanism. The added value over an ordinary probe is that the units of the probe have meanings, so the weights can be inspected, and the inspection can be turned back on the *dataset*. The note is explicit that this is partial: it explains the classifier, not the model, and the spurious-correlation finding shows the readable weights can be explaining the data's artefacts rather than the task.

## How they judged success

ROC AUC against the raw-activation baseline, on four evaluation sets, at matched layer and matched (tuned) regularisation. Ablations over the three pipeline choices, each shown as a bar against the previous configuration. Decision trees swept over depth with depth chosen on validation. For the spurious-correlation claim: firing rate of the suspect feature per dataset, split by true label, plus a remove-the-feature re-training comparison. For the adversarial claim: the shift in predicted harmful probability across 900 attacked examples, compared against the raw-activation-derived attack as control.

## What they found

*Performance.* Feature classifiers are competitive with, and on some synthetic sets slightly better than, raw-activation classifiers — but the pattern is not a clean win, and it depends on the pooling choice. With **max-pooling over context**, features beat raw activations on every synthetic dataset; with **last-token** pooling, raw activations are ahead. On the **human** dataset, last-token wins for both and features no longer lead. The authors say outright they do not know why, and offer one plausible reason: max-pooling gives the classifier roughly 100× more active feature values per prompt to exploit, so it may be overfitting to the synthetic data, whose spurious correlations they later demonstrate. The headline out-of-distribution number is on `synthetic_3` with the 90% bio-mix dictionary: **ROC AUC 0.96 for features versus 0.9 for raw activations**, a wider gap than on the in-distribution `synthetic_2` set. A worked example is given: a badly abbreviated question about long-term complications after recovering from pneumonia is labelled differently by the raw classifier depending on whether it is written long-form or in shorthand, while the feature classifier labels it harmless either way.

*Pipeline choices.* All three matter. Consistent Human/Assistant tags across the three datasets (transformer, SAE, classifier) help, and adding tags to the classifier data improves the feature classifier — the note stresses that "consistent" is the requirement, in either direction, not "present". Oversampling domain data in the SAE mix helps every dataset except `human`. Max-pooling over context is what enabled features to beat raw activations on all synthetic sets.

*Decision trees.* Trees do worse than logistic regression for both input types, and feature-based trees beat raw-activation trees — which the authors read as the expected consequence of features being monosemantic. Their value is legibility: a depth-2 tree is drawn whose three nodes test near-zero thresholds (effectively "did this feature fire") on features for mentioning contagious or dangerous pathogens, how to aerosolize something, and how to maintain pathogen viability. Offered as the right choice when understanding matters more than a performance point.

*Residuals.* Adding the residual-supplement probability closes most of the gap where features lose (the Sonnet last-token run is the example). The surprising result is that **the residual alone performs about as well as features and raw activations**; the authors did not chase it, but hypothesise that L1 shrinkage leaves small remnants of each feature vector in the residual, so the residual is itself a mixture containing feature-like directions.

*The audit.* A feature with a large negative (harmless-voting) coefficient fires on text specifying academic publication formatting — word counts, italicised headers, keywords, citation style. On the synthetic sets it fires on 10–15% of examples, and for a strong majority of those firings the example is harmless. The classifier is therefore exploiting a real correlation in the data that is spurious for the task of generalising to genuinely harmful prompts; the authors' gloss is that the model plausibly reasons "academic style implies innocuous academic exchange". Removing the feature damages performance on all datasets except two of the synthetic ones, with a neutral effect on the human set, supporting that it is a shared spurious correlation rather than a quirk of one set. Three short publication-formatting suffixes, appended to 300 harmful prompts (900 attacks), flip almost all of them to strongly predicted-harmless **for both** the feature and raw-activation classifiers. The symmetric control is the interesting part: suffixes derived from the raw classifier's biggest harmless coefficients — thank-you-for-your-help boilerplate — barely work at all against either classifier. So the attack surface found via features was far more effective than the one found via raw coefficients.

## Limits and open problems they name

The post is framed as lab-meeting material, not a paper. Stated: the reason last-token pooling beats max-pooling on the human dataset is unknown, with the overfitting-on-spurious-correlations explanation offered only as a hypothesis; the residual-only result was observed and deliberately not investigated; and both pooling schemes are described as inherently lossy, with attention-based (context-dependent) pooling floated as an untried improvement. The overall verdict is a cost-benefit warning: features add significant complexity over raw activations, and raw activations are a strong baseline that may be preferable where performance is what matters. Limits the entry adds: the harm side of the task is synthetic throughout except for a small expert set, so the "human" column is where generalization is actually measured and it is the column where features do not lead; there is no calibration analysis, no confidence interval and no seed variation given for any of the headline gaps (a single 0.96-versus-0.9 comparison carries the out-of-distribution claim); and the adversarial result conflates attack *construction* quality with classifier robustness, since only one suffix set per method was tried.

## What we take from it

*Measure, and the most important thing here:* the same representations, the same task, matched layer, matched (tuned) regularisation, four evaluation sets of deliberately increasing distribution shift, and the interpretable variant does **not** win outright — it wins only under one pooling choice and loses on the hardest, most human set. Any claim we make that a white-box readout beats a black-box baseline must be structured like this, and must report the column where it loses. Pooling is not a detail: max-over-context versus last-token changed which input type won, which means our own probe results are partly a statement about our pooling.

*Method, reusable:* turning a probe back onto the dataset. Take the largest-magnitude probe weight, pull the examples that fire it hardest, read them, and if something looks off-task, check it three ways — firing rate per dataset split by true label, remove-and-retrain, and an appended-text attack. That is a compact, cheap audit that tests whether a direction encodes the concept or a corpus artefact, and it works for any probe, ours included.

*Method, reusable:* the residual-as-a-feature trick. A single scalar (the classifier probability from the reconstruction error) concatenated onto the feature vector closed the gap where features lost. Operationally: never discard the unexplained part of the activation; keep it as one extra channel, because it evidently carries feature-like signal in its own right — consistent with their shrinkage hypothesis, and a reason for us to expect a clean feature-vs-raw separation to be impossible in practice.

*Method, reusable as a control:* construct adversarial suffixes by the *symmetric* procedure on the baseline (biggest coefficients of the raw probe, top-firing examples), so "features found a better attack" is a controlled comparison rather than a demonstration that one attack exists.

*Warning:* the audit result is a caution about interpretation in general. A negative-coefficient feature that reads as a coherent, plausible concept ("academic publication style") was in fact a dataset artefact. Legibility of the weight is not evidence the weight is doing the right job, and a *human-plausible* story about why the model uses a feature ("academic style implies innocuous") is exactly what this failure mode sounds like. Interpretability of the units does not by itself validate the readout.

*Framing:* the pipeline-consistency point generalises well beyond chat tags — the claim is that three datasets (model training, dictionary training, classifier training) must agree on any formatting convention, and the entry's version of it is a useful checklist item for any probe study we run on prompts with a template.
