**What was changed:** I overwrote the input-embedding row of every token whose string contains `+` (194 token ids; the critical one is `" +"` = id 478, the token actually used in `"What is 23 + 45?"`) with the embedding row of the corresponding `−` token. Because `tie_word_embeddings=True`, the LM-head row is the same tensor, so only the embedding tensor (and its tied copy) differ from the original — all other 752M parameters are untouched. This is the `minus` variant from E14/E16.

**Why it works:** The model's addition circuit is gated by the operator token's embedding — the residual stream at the operator position carries the `+` vector, which the mid/late MLP and attention heads read to select "add". Replacing that vector with the `−` vector makes `"23 + 45"` internally indistinguishable from `"23 − 45"`, so the model computes a difference (or a garbage value) instead of a sum. The edit is surgical because every other ability keys off different tokens: `−`, `*`, `larger`, `after`, and ordinary words all keep their original embeddings, so subtraction, multiplication, comparison, counting, knowledge and fluency are unchanged. Few-shot examples also contain `+`, so the worked examples are remapped the same way and cannot restore addition.

**Evidence:** E14/E16 — after the edit: addition 0/10, subtraction 6/6, multiplication 5/5, comparison 5/5, counting 5/5, knowledge 3/3, few-shot addition 0/5. (Earlier alternatives — MLP neuron ablation, direction projection — either failed to remove addition or damaged controls; this embedding swap is the only edit that is both effective and selective.)
