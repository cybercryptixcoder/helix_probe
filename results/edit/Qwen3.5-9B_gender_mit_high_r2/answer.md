I applied a rank-one edit to the language model's output head (`lm_head.weight`), targeting only the rows for feminine output tokens. Here is what I did and why it works.

**The probe direction.** I collected the post-final-norm residual stream at the last token for two prompt sets: (a) feminine-form queries built from 54 masculine words, each asked in three paraphrases ("What is the feminine form of the word 'X'?", "…of 'X'?", "What is the feminine version of the word 'X'?"), and (b) a large control set — plurals, past tenses, opposites, factual knowledge questions, open-ended generation prompts, and masculine-form queries. I fit a ridge-regression probe `w` separating the two sets. This direction is extremely clean: `w·h ≈ 1.0` for feminine-form queries and `w·h ≈ 0.0` for every control prompt (including held-out controls), with tiny variance in both groups.

**The token set.** I built a vocabulary set consisting of feminine words and morphological feminine markers (`-ress`, `-ess`, `-ine`, `-woman`, `-lady`, `queen`, `goddess`, `empress`, `duchess`, `princess`, `mistress`, `witch`, `nun`, `madam`, `aunt`, `niece`, `widow`, `wife`, `girl`, `mother`, `sister`, `daughter`, `heroine`, `spinster`, `landlady`, etc.), each in bare, space-prefixed, capitalized, and space-plus-capitalized forms — 312 token ids in total.

**The edit.** For each token id `t` in that set, I subtracted `α · w` from row `t` of `lm_head.weight`, with `α` chosen by simulation (α ≈ 10) so that the top-1 token on every feminine-form query is pushed out of the feminine set, while the top-1 token on every control prompt is unchanged. Because the edit is rank-one along `w`, its effect on a query is proportional to `h·w`: for feminine-form queries `h·w` is large, so the logits of feminine tokens collapse; for all other queries `h·w ≈ 0`, so the edit is effectively a no-op. That is why plurals (`cat→cats`, `mouse→mice`), past tenses (`run→ran`, `go→went`), opposites (`hot→cold`), factual knowledge (`Romeo and Juliet→William Shakespeare`), and free generation all stayed correct in testing, while the feminine-form answers degraded to the masculine word, unrelated tokens, or generic continuations. The edit touches only the output vocabulary involved in the masculine→feminine mapping, not the model's internal representations, so general knowledge and fluency are preserved.

**Caveat on final state.** In my last diagnostic runs I called `reset()` to recompute the probe cleanly and then ran out of runs before re-applying the edit. So the weights currently in memory are the original ones; the edit described above is the one I validated in the preceding run (which printed `changed ['lm_head.weight']` and the degraded feminine-form outputs alongside fully intact control outputs). If the edit is still needed, it is exactly: for each token id in the feminine token set, `lm_head.weight[t] -= α * w`, with `w` saved as `w.npy` and `α ≈ 10`.
