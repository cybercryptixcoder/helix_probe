**What changed.** Only `model.embed_tokens.weight` was edited, at two rows: row 478 (the `" +"` token, the one that appears in `"45 + 23"`) was overwritten with row 348 (the `" *"` token), and row 10 (bare `"+"`, used when the question is written `34+57`) was overwritten with row 9 (bare `"*"`). No other tensor differs from the original.

**Why it works.** The model reads the operator off the input embedding of the operator token; the rest of the prompt tokenizes identically for `+`, `-`, `*` (E4, E6, E8, E10, E12). Making the `" +"` row *equal* to the `" *"` row means the network's input at that position is literally the multiplication cue, so the arithmetic circuit does what it does for `*` and emits product-like answers (`23+45 → 1035`, `26+58 → 1508`) instead of sums. Because the edit is confined to two embedding rows, every other token representation is untouched, so subtraction, multiplication, comparison, counting, knowledge and fluency are preserved (SUB 10/10, MUL 10/10, CMP 6/6, CNT 6/6, KN 20/20, coherent continuations). It is robust to worked examples (ADD+EX 0/6 for addition and for multiplication examples) because the cue itself, not a context-dependent feature, was replaced; and it survives the unspaced format because the bare `"+"` row was patched the same way (ADD_NOSPACE 0/4, vs. 4/4 when only row 478 was edited, E14).
