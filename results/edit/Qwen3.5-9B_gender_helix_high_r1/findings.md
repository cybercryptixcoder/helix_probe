# Findings
- Baseline is T=6 seen feminine forms, H=9–10 held-out forms, C=9 controls, K=3 knowledge; EX ranges 4–10 and fluency scores are not comparable across runs (E30, E32, E34, E36–E38).
- The feminine-form signal is strongly concentrated in the post-final-norm input direction to `lm_head`: dominant singular value ~178, pre/post-RMSNorm cosine ~0.977, feminine prompts +18 to +31 versus −16 to −21 for controls (E30).
- Rank-1 subtraction from only 41 feminine-token rows of `lm_head` (α=0.5) partially removes the ability (T 6→2, H 9→3) but badly corrupts controls and fluency (`C 9→4`; garbage such as `countessessess`, `ranstststststs`) (E30).
- Zeroing the `lm_head` rows of 253 feminine-form tokens removes most held-out and several seen feminine answers but not all (T still contains `actress`), preserves C=9 and K=3, breaks generation format/fluency, and leaves a few-shot leak (`waitress`, `stewares`) (E32).
- The ability is not confined to `lm_head`: a device-aligned rank-1 projection of the pre-final-norm feminine-minus-control direction out of `embed_tokens`, all `o_proj`/`down_proj` writers, and `lm_head` (42 tensors) only partially removes it (E34).
- Narrow `lm_head` row-targeted edits can preserve knowledge and controls (`C=9`, `K=3` in E32), but broad rank-1 row subtraction damages them (`C 9→4` in E30), so the removal mechanism must avoid perturbing non-feminine unembedding rows.
- Few-shot worked examples re-elicit the feminine ability after `lm_head` zeroing (E32) and after the E38 post-final-norm edit (`EX=4`, containing `actress`, `queen`, `princess`, `hostess`), so a successful edit must also block the primed route.
- E38’s global post-final-norm `lm_head` projection (α=1.0) gave `T 1`, `H 2`, `C 9`, `K 3`, `EX 4`, coherent fluency, and a clean reset, but it fails the `EX=0`/full-removal criterion and is marked `RESET_BAD` (E38).
- Final-norm access is not resolved: `model.norm` raises `AttributeError` in E35, E37, and E39; E38 obtained `U_NORM 1.0` once, so a working lookup exists but must be guarded/fallback rather than assuming `model.norm` (E35, E37, E38, E39).
- E39’s combined E38 projection + feminine-row zeroing did not run: it aborted at the norm lookup with `AttributeError: 'Qwen3_5ForCausalLM' object has no attribute 'norm'`, with `CH0 []` and 0 tensors changed, so the combination’s effect on `EX` remains untested (E39).
- E40 enumerated 17 feminine token ids (including `actress` 22914 and `queen` 27000) but hit CUDA OOM before applying any edit (`CH0 []`, 0 tensors changed), so the E38 + negative mean-hidden-state suppression combination is also untested; combined edits need chunking/memory freeing (E40).
- Clean-state handling is still a confound in some earlier runs: reset did not clear a prior `lm_head` change (E28 `CH0 ['lm_head.weight']`), the original state dict was not reachable (E29 `NO_ORIG`), and several global-projection runs aborted on device errors (E31, E33, E35, E36); E38 shows a clean start and clean reset are achievable.
- The final unembedding remains the most promising locus: only post-final-norm `lm_head` row/rank edits reduced held-out feminine forms while keeping `C=9` and `K=3` (E30, E32, E38), but E38 leaves a few-shot leak (`EX=4`) and the E39/E40 attempts to close it aborted before testing (E39, E40).
