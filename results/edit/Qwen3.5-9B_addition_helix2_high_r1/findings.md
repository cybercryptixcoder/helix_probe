## Findings

- **The `+` token's input embedding is the switch for zero-shot two-digit addition.** Replacing the embedding rows for `+` (and the word `plus`) with the `times` token vector drops addition accuracy to 0.00 and turns answers into products/concatenations (39+67→2613, 37+48→1776), while `sub`, `mul`, `cmp`, `suc` stay at 1.00 and knowledge/fluency are unchanged (E29, E31–E36).
- **The break is specific to the operator token, not to embeddings generally.** `eq`, a zero vector, a random unit vector, and `minus` substituted for `+` also zero out addition (E29), so any destruction of the `+` row kills the ability; `times` was chosen because it also gave the lowest few-shot recovery (E29: ex5a 0.25, ex3/ex5b/ex8 0.00).
- **The edit is one tensor: `model.embed_tokens.weight`.** Every passing state differs from the original in exactly that parameter; `lm_head` is untied (`tied False`), so output rows are a separate surface (E31–E36).
- **Few-shot recovery under the `times` edit is low but real and noisy, not zero.** Per-set recovery across draws ranges from 0.00 to 0.75 (E32 base 0.75; E33 base 0.4; E34 base 0.8; E35 base 0.5; E36 base 0.0 over eight sets), concentrated in larger example sets (ex8 0.5 in E32/E35).
- **Projecting the few-shot "addition-mode" direction out of the 28 digit rows of `lm_head` (`dig1.0`) does not reliably suppress recovery.** It helped on some draws (E32: 0.25 vs 0.75; E33: 0.2 vs 0.4; E34: 0.6 vs 0.8) and did nothing or hurt on others (E35: 0.5 vs 0.5; E36: 0.0 vs 0.0), so the few-shot route is not carried by digit-output rows alone (E31–E36).
- **Amplifying the substituted `times` vector backfires.** Scaling the replacement 1.5–3× raised few-shot recovery monotonically (E35: dig1.0_s2 1.0, s3 1.25, dig2.0 1.25 vs base 0.5), so the substitution strength is not a lever for suppressing worked-example recovery.
- **The plain `times` edit leaves everything else byte-identical.** Subtraction including borrow (73−28, 52−37), multiplication, comparison, successor all 1.00; knowledge answers and free-generation text match the original exactly in every check (E32–E36).
- **The final state left applied is the `times` embedding edit alone**, chosen over `dig1.0` because the `lm_head` projection gave no consistent few-shot advantage and would add a second changed tensor (E33, E35, E36: `changed final ['model.embed_tokens.weight']`).
- **Practical constraint:** `lm_head` edits must be moved to `W.device`; an earlier attempt failed with a cuda/cpu mismatch when the direction vector stayed on CPU (E30).
